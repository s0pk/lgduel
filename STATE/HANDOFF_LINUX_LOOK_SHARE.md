# LGDuel — handoff plan: native Linux (Arch first), look & feel, share codes

## Context
LGDuel (Rust workspace, wgpu 30 + winit 0.30 + egui 0.37, repo root = this folder) is feature-complete for v0.2 plus
themes and enemy models (`STATE/HANDOFF_VISUALS.md`, done). This plan, written for a cheaper model to follow, adds:

- **Part A — Native Linux**, installable on **Arch Linux** with an **AUR source package** (`lgduel`, plus `lgduel-server`
  with systemd service). Linux has never been built or run here (KI-1): A1 does that first.
- **Part B — Share codes**: export/import your look and settings as one pasteable code (`LGP1-…`), built-in presets,
  and single-file theme packs (`.lgtheme`).
- **Part C — Look & feel**: app icon, anti-aliasing option, HUD/UI scaling, crosshair styles, procedural sound set,
  better menu styling, sky gradient + edge outlines + more built-in themes, scoreboard overlay.

User decisions (2026-10-23): look sharing is **local only** (nobody sees your skin online; no protocol change);
Arch packaging = **AUR source package** (other formats are out of scope: note them in INSTALL.md as "not yet").

Everything is client-side except packaging; **no change to the network protocol, server, simulation or bots.**

Order: A1 → A5, then B1 → B4, then C1 → C8 (C items are independent; do them in any order after B1). Each milestone =
one commit with `./scripts/check.sh` green.

## 0. Ground rules (read first; same spirit as `HANDOFF_VISUALS.md` §0)

1. **Per milestone:** implement → `cargo fmt --all` → `cargo clippy --workspace --all-targets --release -- -D warnings`
   → `./scripts/check.sh` (Git Bash on Windows, ~2 min, must end `CHECK GREEN`) → one commit with the trailer
   `Co-Authored-By: <your model name> <noreply@anthropic.com>` → tick the item in `STATE/PLAN.md`, append to
   `STATE/PROGRESS.md` (what changed, what you verified) and add a `D<n>` entry to `STATE/DECISIONS.md` for design choices.
   Never weaken, skip or delete an existing test or check.
2. **Default look stays pixel-identical** (classic theme, classic model, forced colours, defaults of every new setting).
   `run_headless` in `crates/client/src/main.rs` counts exact colours; new options default to off / current behaviour.
   New looks get their own extra check runs in `scripts/check.sh` with their own assertions.
3. **Simulation untouched:** `cargo test -p lgduel-sim --test determinism` golden hash `0x9e74a8ea7918ee78` must not change;
   `World::content_hash()` ignores visuals. Protocol stays at version 9.
4. **Visibility first:** no fog, no screen shake/flash/blood (tests in `scene.rs` assert it), forced enemy colours default on.
5. **Legal:** only original or generated assets (CC0/MIT). Icons/sounds/textures are generated by code or drawn by you.
6. **Performance:** ≥ 1000 FPS at 1080p on the dev PC:
   `target/release/lgduel --no-settings --practice --synthetic-input --frames 4000 --size 1920x1080` → `FRAMESTATS`.
7. **Safety of imported data:** share codes, theme packs and drag-and-dropped files come from strangers. Whitelist keys,
   cap sizes before allocating, never write outside the themes folder, never execute anything. Each such feature has
   tests with hostile input.

### Gotchas already hit (don't rediscover them)
- Shell = Git Bash on Windows. **Never put Python or Rust with backslashes/quotes in a bash heredoc**: use the Write tool
  to create a script file (e.g. in the scratchpad) and run that. Use the Edit tool for code edits.
- **wgpu 30**: `depth_write_enabled: Some(true)`, `depth_compare: Some(..)`, `entry_point: Some("vs")`,
  `bind_group_layouts: &[Some(&bgl)]`, `multiview_mask: None`, `cache: None`, `wgpu::MipmapFilterMode`, `wgpu::TexelCopyTextureInfo`.
  Source: `~/.cargo/registry/src/*/wgpu-30*/` and `wgpu-types-30*`.
- **egui 0.37**: `egui::Id::new` deprecated (use `Id::unique`); panels need a parent `Ui` (use `Area`/`Window`);
  `ComboBox::from_id_salt`; copy to clipboard with `ui.ctx().copy_text(string)`.
- **png 0.18**: `png::Decoder::new(Cursor::new(bytes))` (needs `BufRead + Seek`); see `textures::decode_png` for the pattern.
- The HUD pixel font has uppercase, digits and some punctuation only (no "…", no lowercase glyphs).
- clippy `-D warnings` bites: `type_complexity` (add a `type` alias), `large_enum_variant` (`#[allow]` with a reason or box),
  `chunks_exact` with constant size (use `as_chunks::<N>().0`), `needless_range_loop`, `wrong_self_convention` (`from_*` methods).
- HashMap iteration order is random: use `BTreeMap` anywhere a value is hashed/serialised.
- Settings structs are `#[serde(default)]`; every setting is automatically a console variable
  (`crates/client/src/console.rs` walks the serialised `Settings`).

### Existing code map you will touch
`crates/client/src/`: `main.rs` (Options/CLI `parse_args`, `run_headless*`, `App`, window creation in `resumed`, `refresh_style`),
`settings.rs` (Settings, `default_path`), `menu.rs` (screens, `visuals_tab`, `Tab`, `Menu`), `console.rs` (`run`, `ConsoleAction`),

Packaging: `scripts/package.sh`, `.github/workflows/{ci,release}.yml`, `deploy/` (server systemd units, `install.sh`), `Dockerfile`.

# Part A — Native Linux + Arch install

### A1 — Build, test and fix on real Linux
Goal: `./scripts/check.sh` green on Linux (closes KI-1). The dev PC has **WSL2 Ubuntu** (`wsl -l -v` lists `Ubuntu`, stopped).
1. Start it: `wsl -d Ubuntu`. Inside (use the Linux filesystem, not `/mnt/c`, builds are 10× faster):
   ```
   sudo apt-get update && sudo apt-get install -y build-essential pkg-config libasound2-dev mesa-vulkan-drivers libvulkan1 python3 git curl
   curl https://sh.rustup.rs -sSf | sh -s -- -y      # rustup then installs the toolchain pinned in rust-toolchain.toml
   git clone /mnt/c/Users/sopk/lgduels ~/lgduels && cd ~/lgduels && git checkout v0.2-dev
   ./scripts/check.sh
   ```
   `mesa-vulkan-drivers` includes lavapipe (software Vulkan), so the offscreen render checks work without a GPU.
2. Fix whatever breaks, in the repo (not in the WSL copy; commit on the Windows side, `git pull` into WSL to retest). Known suspects:
   `python` vs `python3` in `scripts/package.sh` (use `python3` if `python` is missing), Windows-only paths/`.exe` in scripts,
   tests that assume Windows line endings or a drive letter (`textures::safe_relative` test strings are fine),
   `cpal` needing `libasound2-dev` at build time.
3. Audio on Linux: if no ALSA device exists the game must keep running muted (`Audio::silent`) — verify by running
   `target/release/lgduel --headless --frames 3` and a windowed run under WSLg (`target/release/lgduel --practice --no-settings`
   shows a window via WSLg; mouse grab may be limited there, that's fine).
4. Record results in `STATE/PROGRESS.md` (distro, GPU/lavapipe, what had to change). Update KI-1 as resolved.
Done when: check.sh GREEN in WSL Ubuntu with no skipped stage.

### A2 — Linux platform behaviour (code)
Files: `settings.rs`, `theme.rs` (`search_dirs`), `main.rs` (window creation + CLI), `gfx.rs`.
1. **Folders (XDG).** `settings::default_path()` already uses `$XDG_CONFIG_HOME/lgduel`. Add Linux theme search dirs in

   `/usr/share/lgduel/themes`. Gate with `#[cfg(target_os = "linux")]` but keep the function testable: put the Linux list in a

3. **Mouse grab check.** `App::set_grab` tries `Locked` then `Confined` (correct: X11 only supports Confined, Wayland supports

5. **Print the platform in the startup banner** (backend, adapter already printed) and add `lgduel --doctor`: prints OS, session type

Tests: `linux_theme_dirs` unit test; `--doctor` run in check.sh (`"$T/$PROFILE/lgduel" --doctor | grep -E "^adapter"`).

### A4 — AUR source package `lgduel` (+ `lgduel-server`)
Files: new `packaging/arch/PKGBUILD`, `packaging/arch/lgduel-server.install` (optional), `packaging/arch/lgduel.sysusers`,
`packaging/arch/lgduel-server.service` (derived from `deploy/lgduel-server.service` with `/usr/bin` paths), `packaging/arch/README.md`.
One PKGBUILD, split packages (pkgbase pattern):
```bash
pkgbase=lgduel
pkgname=(lgduel lgduel-server)
pkgver=0.2.0
pkgrel=1
pkgdesc='Lightning Gun duel trainer: vamp mode, practice bots, online duels'
arch=(x86_64)
url='https://github.com/s0pk/lgduel'
license=(MIT)
makedepends=(rust cargo)
source=("$pkgbase-$pkgver.tar.gz::$url/archive/refs/tags/v$pkgver.tar.gz")
sha256sums=('SKIP')            # replace with the real sum after the tag exists: updpkgsums
options=(!lto)                 # the project sets its own profile

prepare() {
  cd "$pkgbase-$pkgver"
  export RUSTUP_TOOLCHAIN=stable          # ignore rust-toolchain.toml's rustup pin; Arch's rust is current
  cargo fetch --locked --target "$(rustc -vV | sed -n 's/host: //p')"
}
build() {
  cd "$pkgbase-$pkgver"
  export RUSTUP_TOOLCHAIN=stable CARGO_TARGET_DIR=target
  cargo build --frozen --profile dist -p lgduel-client -p lgduel-server -p lgduel-bot
}
check() {
  cd "$pkgbase-$pkgver"
  export RUSTUP_TOOLCHAIN=stable CARGO_TARGET_DIR=target
  cargo test --frozen --release -p lgduel-sim -p lgduel-net -p lgduel-server   # no GPU or network needed
}
package_lgduel() {
  depends=(alsa-lib vulkan-icd-loader libxkbcommon wayland libx11 libxcursor libxi libxrandr)   # verify with namcap
  optdepends=('vulkan-radeon: AMD GPU' 'nvidia-utils: NVIDIA GPU' 'vulkan-intel: Intel GPU'
              'pipewire-alsa: sound on PipeWire systems' 'pulseaudio-alsa: sound on PulseAudio systems'
              'lgduel-server: host a dedicated server on this machine')
  cd "$pkgbase-$pkgver"
  install -Dm755 target/dist/lgduel     "$pkgdir/usr/bin/lgduel"
  install -Dm755 target/dist/lgduel-bot "$pkgdir/usr/bin/lgduel-bot"
  install -Dm644 packaging/lgduel.desktop "$pkgdir/usr/share/applications/lgduel.desktop"
  for s in 48 128 256; do install -Dm644 assets/icons/lgduel-$s.png "$pkgdir/usr/share/icons/hicolor/${s}x${s}/apps/lgduel.png"; done
  install -dm755 "$pkgdir/usr/share/lgduel/themes" && cp -r assets/themes/example "$pkgdir/usr/share/lgduel/themes/"
  install -Dm644 LICENSE "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
  install -Dm644 README.md PLAY.md THEMES.md MAPS.md CONFIG.md HOSTING.md INSTALL.md -t "$pkgdir/usr/share/doc/lgduel/"
}
package_lgduel-server() {
  pkgdesc='LGDuel dedicated server and join-code relay (systemd services)'
  depends=(glibc)
  backup=(etc/lgduel/server.toml)
  cd "$pkgbase-$pkgver"
  install -Dm755 target/dist/lgduel-server "$pkgdir/usr/bin/lgduel-server"
  install -Dm644 config/server.example.toml "$pkgdir/etc/lgduel/server.toml"
  install -Dm644 packaging/arch/lgduel-server.service "$pkgdir/usr/lib/systemd/system/lgduel-server.service"
  install -Dm644 packaging/arch/lgduel-relay.service  "$pkgdir/usr/lib/systemd/system/lgduel-relay.service"
  install -Dm644 packaging/arch/lgduel.sysusers "$pkgdir/usr/lib/sysusers.d/lgduel.conf"     # contents: u lgduel - "LGDuel server" -
  install -Dm644 LICENSE "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
  install -Dm644 DEPLOY.md HOSTING.md -t "$pkgdir/usr/share/doc/lgduel-server/"
}
```
Notes for the implementer:
- The `dist` profile (`Cargo.toml`) already exists (LTO, stripped). Binaries are Linux ELF; `crt-static` in `.cargo/config.toml` is Windows-only.
- Systemd units: copy `deploy/lgduel-*.service`, change `ExecStart` to `/usr/bin/lgduel-server --config /etc/lgduel/server.toml`
  (relay: `/usr/bin/lgduel-server relay --port 27950`), keep `User=lgduel` and the hardening lines; `Wants=network-online.target`.
- Do **not** run `useradd` in the package: `sysusers.d` creates the user (Arch packaging rule).
- Verify what you can: `makepkg --printsrcinfo > .SRCINFO` is text, test it against the PKGBUILD in a unit-ish script

- **Building the package for real** needs an Arch environment. Options, in order: (a) `wsl --list --online`: if `archlinux` is listed,
  `wsl --install archlinux` (ask the user first, it downloads ~500 MB), then `pacman -S base-devel git` and `makepkg -s` in a copy of the repo with

  the GitHub billing lock); (c) review by reading only, and say so in PROGRESS.md.
- **The user does the AUR submission** (needs an AUR account + SSH key): document the exact steps in `packaging/arch/README.md`
  (`git clone ssh://aur@aur.archlinux.org/lgduel.git`, copy PKGBUILD + `.SRCINFO`, `updpkgsums`, `makepkg -si`, commit, push). The package needs the git

# Part B — Share codes, presets, theme packs

Shared design: a **profile** is a whitelisted subset of the settings. Whitelist = keys (from `console::cvars`) starting with
`video.theme`, `effects.`, `hud.` (except `hud.net_graph`), `enemy_colors.`, `models.`, plus new look settings from Part C
(`hud.*`, `video.msaa`, `audio.*` sound options). **Controls group** (opt-in checkbox/flag): `mouse.`, `video.fov`, `audio.volume`.
**Never included or accepted:** `name`, `servers`, `rendezvous`, `host.*`, `practice.*`, `filter.*`, `video.size`, `video.fullscreen`,
`video.vsync`, `video.fps_cap`.

### B1 — Profile codes (`profile.rs`)
Files: new `crates/client/src/profile.rs`, `console.rs`, `menu.rs`, `main.rs`, `Cargo.toml` (add `flate2 = "1"`, already in `Cargo.lock` through `png`).
Format (version 1): text lines `key value` (value = the TOML text of the setting, e.g. `hud.crosshair.color [1.0, 0.2, 0.6]`), UTF-8,
sorted by key, optional first line `v 1`; compress with `flate2::write::ZlibEncoder` (best), append CRC32 (`crc32fast` is in the lock too; or
`flate2::Crc`), encode **base64url without padding** (write the ~30-line encoder/decoder yourself, no new crate), prefix `LGP1-`.
API:
```rust
pub struct Profile { pub entries: Vec<(String, String)>, pub theme_toml: Option<(String, String)> /* (theme name, theme.toml text), embedded when it has no PNG */ }
pub fn export(s: &Settings, theme_dirs: &[PathBuf], with_controls: bool) -> String        // the code
pub fn decode(code: &str) -> Result<Profile, String>                                      // validates; no side effects
pub fn preview(p: &Profile, current: &Settings) -> Vec<Change>                            // what would change (key, old, new)
pub fn apply(p: &Profile, s: &mut Settings, themes_dir: Option<&Path>) -> ApplyReport     // atomic: all-or-nothing on a clone, uses console::set per entry
```
Rules:
- Decode limits **before allocating**: code ≤ 16 000 chars (whitespace/newlines inside are ignored so pasted wrapped codes work); inflate through
  `Read::take(65 536)` and reject if more; ≤ 300 lines; key ≤ 64 chars; value ≤ 2 000 chars; CRC must match.
- Apply: each entry must be whitelisted (else collected in `skipped`), then `console::set` (type-checked, `Settings::sanitize`d). One bad value → that entry
  skipped with a message, others still apply. Result is committed only if at least one entry applied.
- Embedded theme: if the active theme is a folder theme whose `theme.toml` mentions no `.png`, include its text. On apply, install into `<settings>/themes/<name>/theme.toml`
  (name must pass `theme::safe_theme_name`; if it exists with different content, install as `<name>-2`, `-3`… and point `video.theme` at it). PNG-using themes: the code only
  carries the theme *name* and `ApplyReport.missing_theme = Some(name)` so the UI says "theme X is not installed: ask for the .lgtheme file".
- UI: **Settings → new "Share" tab** (`Tab::Share` in `menu.rs`): checkbox "Include controls (mouse, FOV, volume)", button *Make code* → read-only multiline box + *Copy*
  (`ui.ctx().copy_text`); a paste box (`TextEdit::multiline`), *Preview* (list of `key: old → new`, skipped keys, missing theme) and *Apply*.
- Console: `exportprofile [controls]` prints the code; `importprofile CODE` previews then applies. CLI: `--import-profile CODE` (applies to settings then continues/saves).
Tests (`profile.rs`): round trip equals the original whitelisted subset; non-whitelisted keys in a hand-built code are skipped (`name`, `servers`, `host.port`, `video.size`);
flipped bit → CRC error; truncated; huge input (200 000 chars) rejected without large allocation; zip-bomb style (valid zlib that inflates to 10 MB) rejected; bad value
(`hud.crosshair.size banana`) skipped while a good one applies; wrapped/whitespace-padded code decodes; embedded theme installs under a temp dir and a name collision gets a suffix;
unsafe theme name (`../x`) refused; `with_controls` flag includes/excludes `mouse.cm_per_360`.

### B2 — Built-in presets
Files: `profile.rs` (or `presets.rs`), `menu.rs`, `console.rs`. A `presets()` list of `(name, description, Vec<(key, value)>)` built in code (not hard-coded code strings):
`classic` (all look settings back to defaults), `high-visibility` (thick bright crosshair, thick beam, large HUD text, `grid` theme off), `colour-blind-safe`
(enemy colours chosen for deuteranopia/protanopia/tritanopia legibility: high luminance contrast, e.g. head white-yellow `[1,0.95,0.2]`, upper blue `[0.1,0.35,1]`, lower orange `[1,0.5,0]`; document why),
`minimal` (no beam sparks, no damage numbers, no net-graph), `showcase` (grid theme + humanoid + skins, for screenshots). Apply with the same path as B1
(`Profile` → `apply`). Settings → Share tab lists them with *Apply*; console `preset NAME` / `presets`. Tests: every preset applies cleanly to defaults with zero skipped keys;
`classic` after any other preset returns the look settings to `Settings::default()`; colour-blind preset colours pairwise differ in luminance by ≥ 0.25 (compute relative luminance in the test).

### B3 — Theme packs (`.lgtheme` single files)
Files: new `crates/client/src/themepack.rs`, `main.rs` (drag and drop + CLI), `console.rs`, `THEMES.md`.
Format: magic `LGTH`, u16 version 1, then a zlib stream of `count: u8 (≤ 33)` entries `{name_len: u8, name bytes, data_len: u32, data}`. Allowed names: `theme.toml` and
`*.png` (flat, `textures::safe_relative` and no `/`). Limits: inflated total ≤ 24 MB (take-limited), each PNG ≤ `textures::MAX_FILE_BYTES`, ≤ 32 PNGs, exactly one `theme.toml`.
API: `pack(theme_dir) -> Result<Vec<u8>>`, `unpack_to(bytes, themes_dir, name) -> Result<PathBuf>` (validates **everything first**: parses theme.toml with `Theme::from_toml`,
decodes every PNG with `textures::decode_png`, then writes to a temp folder and renames; never overwrites an existing theme unless `replace` is true).
Entry points: console `exporttheme NAME` → `<settings>/themepacks/NAME.lgtheme`; `importtheme FILE [as NAME]`; CLI `--import-theme FILE`; **drag and drop** an `.lgtheme` onto the
window (`WindowEvent::DroppedFile` in `App::window_event`; also handle it while a menu is open) → import, select the theme, print the result in the console.
Tests: pack→unpack round trip of `assets/themes/example` is byte-identical per file; path traversal names (`../x.png`, `a/b.png`, absolute, `theme.toml.png`) rejected; corrupt PNG inside rejected
and **nothing** left on disk; zip-bomb (small compressed, huge inflated) rejected; two `theme.toml` rejected; name collision refused without `replace`; unpacked theme loads via `ThemeStyle::load` with no problems.
